# Эмулятор командной оболочки (вариант № 4)

Учебный проект: интерпретатор команд с приглашением вида `myvfs:/$`,
работающий с виртуальной файловой системой (VFS) в памяти.
Исходная VFS - обычный каталог на диске. Он читается один раз при запуске
и дальше не изменяется: все команды работают только с копией в памяти.

## Требования

- Python 3.9+
- Для запуска тестов нужен `pytest`:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install pytest
```

## Запуск

```bash
# интерактивный режим
python -m src.main --vfs examples/vfs/nested

# со стартовым скриптом
python -m src.main --vfs examples/vfs/nested --script scripts/stage2.sh
```

Параметры:

| Параметр   | Обязателен | Описание                                      |
|------------|------------|-----------------------------------------------|
| `--vfs`    | да         | путь к каталогу с исходной VFS                |
| `--script` | нет        | путь к стартовому скрипту с командами эмулятора |

При старте выводятся все заданные параметры. Если `--script` не указан,
запускается интерактивный режим. Если скрипт указан, выполняются его команды
(пустые строки и строки, начинающиеся с `#`, пропускаются; каждая команда
печатается вместе с приглашением и результатом), после чего программа
завершается. Встретившийся в скрипте `exit` прекращает выполнение скрипта.

Вспомогательные запускающие файлы: `run.sh`, `run.bat`, `scripts/run_*.sh`
(на Windows - через Git Bash).

## Команды

| Команда               | Описание                                                        |
|-----------------------|-----------------------------------------------------------------|
| `ls [путь]`           | содержимое текущего или указанного каталога (каталоги с `/`)    |
| `cd путь`             | смена каталога: `имя`, `..`, `/`, `.`, вложенные пути           |
| `whoami`              | имя пользователя эмулятора (`student`)                          |
| `who`                 | условная сессия: `student console`                              |
| `tree [путь]`         | дерево каталогов и файлов                                       |
| `mv источник назн.`   | перемещение/переименование только в памяти                      |
| `vfs-save путь`       | сохранение текущего состояния VFS в каталог на диске            |
| `exit`                | выход                                                           |

Принятые решения:

- Аргументы разделяются пробелами (кавычки не поддерживаются).
- `ls` и `tree` с путём к файлу, `cd` в файл, `cd` без аргумента - ошибка.
- `mv` не перезаписывает существующие объекты, не переносит каталог внутрь
  самого себя и не переносит корень. Все проверки выполняются до изменения дерева.
- `vfs-save` сохраняет VFS в обычный каталог (тот же формат, что и исходный)
  и не перезаписывает уже существующий путь.
- Файлы хранятся в виде байтов, поэтому содержимое не меняется при сохранении.

## Ошибки загрузки

```
Ошибка VFS: указанный путь не существует.
Ошибка VFS: ожидается каталог.
```

Если файл не удалось прочитать, сообщение называет проблемный объект,
и эмулятор не запускается с частично загруженной VFS.

## Структура проекта

```
src/        main.py, shell.py, parser.py, vfs.py, commands.py
tests/      test_parser.py, test_vfs.py, test_commands.py
scripts/    сценарии эмулятора (stage*.sh) и запускающие скрипты (run_*.sh)
examples/   три тестовые VFS: minimal, several_files, nested
```

## Тесты

```bash
python -m pytest -v
```

Проверка изоляции VFS (mv не трогает диск, vfs-save сохраняет изменённое):

```bash
./scripts/check_isolation.sh
```
